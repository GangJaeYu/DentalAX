## 2. 로그인·권한·세션
| 항목 | 상태 | 어떻게 |
|---|---|---|

| 기본 비밀번호 없음, 첫 실행 설정 화면 | ✅ | 사용자가 0명일 때만 `/api/auth/setup` 허용, 이후 409 |

| 임시 비밀번호 강제 변경 | ✅ | 관리자가 만든/초기화한 계정은 첫 로그인 시 변경 전까지 업무 API 403 |
| 로그인 시도 제한 | ✅ | 계정당 5회 실패 → 15분 잠금, IP당 15분 30회, 없는 아이디도 같은 시간 소요(계정 존재 추측 방지) |

## 3. 웹 공격 방어
| 항목 | 상태 | 어떻게 |
|---|---|---|
| CSRF | ✅ | ① 세션별 CSRF 토큰을 `X-CSRF-Token` 머리글로 확인 ② Origin 검사 ③ JSON(또는 복원 파일)만 허용 → 일반 웹 폼으로 위조 불가 ④ SameSite=Strict |
| XSS | ✅ | 화면은 Preact 템플릿(자동 이스케이프), `innerHTML` 미사용, 마크다운은 안전한 요소로 직접 변환(`ui/markdown.js`), CSP `script-src 'self'`(인라인 스크립트 불가), E2E로 `<img onerror>` 삽입 무해 확인 |
| SQL 인젝션 | ✅ | 모든 SQL은 `?`/`:이름` 자리표시자. 정렬 등 동적 부분은 허용 목록. 테스트로 `' OR 1=1 --` 검색 확인 |
| 입력값 검증 | ✅ | `server/core/validate.js` — 길이·형식·날짜·허용 값, 제어문자 제거. 잘못되면 400 + 한국어 안내 |
| 보안 헤더 | ✅ | CSP(default-src 'self', frame-ancestors 'none', object-src 'none'), X-Content-Type-Options, X-Frame-Options DENY, Referrer-Policy no-referrer, Permissions-Policy, CORP(COOP는 HTTPS 전용이라 원내 HTTP에선 제외), API 응답 no-store, X-Powered-By 제거 |
| 경로 조작 | ✅ | 정적 파일은 `public/` 밖 접근 불가, 백업 파일 이름은 정해진 형식만 허용 |
| 파일 업로드 | ✅ | 크기 제한(20MB), 내려받기 시 위험 형식(html·svg·js)은 `application/octet-stream` + nosniff, 파일은 DB에 저장(실행 불가) |
| CSV 수식 공격 | ✅ | 내보낼 때 `= + - @` 로 시작하는 칸 앞에 `'` |
| 오류 정보 숨김 | ✅ | 예상 못한 오류는 서버 창에만 기록, 화면엔 일반 안내 |
| 요청 크기 제한 | ✅ | JSON 30MB, 복원 파일 500MB |
| AI 남용 방지 | ✅ | 사용자당 1분 30회, 월 예산 한도 |

## 7. 남은 위험과 권장 조치
1. 원내 와이파이를 환자용과 분리하세요(손님 와이파이에서 서버 PC가 보이지 않게).
2. 서버 PC에 Windows 계정 비밀번호와 자동 화면 잠금을 설정하세요.
3. 직원 교육: AI 입력창에 환자 정보 금지, 비밀번호 공유 금지, 퇴사자 계정 즉시 비활성화.
4. 분기마다 `npm run audit` 로 취약점을 확인하고 Node.js LTS 업데이트를 적용하세요.
5. 이 점검은 개발자 자체 점검이며 외부 보안 감사를 대신하지 않습니다.
