# 결정 기록 (DECISIONS)

> 작업 중 사용자에게 묻지 않고 정한 것들과 그 이유입니다. 바꾸고 싶으면 이 문서를 근거로 Claude Code에 요청하세요.

## D-01. 기술 스택: Node.js + Express + SQLite(Node 내장) + 빌드 없는 화면(Preact + htm)
- **Node.js 24 LTS 이상**: Windows 설치 프로그램이 클릭 몇 번으로 끝나고, 가장 대중적인 서버 기술입니다.
- **DB는 Node에 내장된 `node:sqlite`**: 별도 DB 프로그램 설치가 없고, 데이터가 `data/dentalax.db` 한 파일입니다.
  흔히 쓰는 `better-sqlite3`는 Node 버전에 따라 C++ 빌드 도구(Visual Studio)가 필요할 수 있어 비개발자 설치에서 가장 자주 막히는 지점이라 피했습니다.
  내장 SQLite는 아직 "실험적 기능" 표시가 붙지만 Node 24에서 플래그 없이 동작하며, 쓰는 기능(기본 SQL, 트랜잭션, `VACUUM INTO`)은 안정적인 SQLite 자체 기능입니다.
- **서버 프레임워크는 Express 5 하나만** 실행 의존성으로 씁니다. 가장 널리 쓰여 나중에 고치기 쉽습니다.
  비밀번호 해시(scrypt), 암호화(AES-GCM), 테스트(node:test)는 모두 Node 내장 기능으로 해결해 의존성을 줄였습니다.
- **화면은 빌드 과정이 없는 방식**: Preact(React와 같은 방식의 3KB 라이브러리)와 htm을 파일 하나로 프로젝트에 넣었습니다.
  `npm run build` 같은 단계가 없어서, 파일을 고치고 새로고침하면 바로 반영됩니다. 인터넷이 없어도 화면이 뜹니다.
- **AI 공급자 SDK를 쓰지 않고** 공식 REST API를 `fetch`로 직접 호출합니다. 의존성이 줄고 공급자 추가가 쉽습니다.

## D-02. 업로드 파일은 DB 안에 저장
서식 보관함 파일과 원내 문서를 DB 안(BLOB)에 넣습니다. 그래서 **백업 = DB 파일 하나 복사**로 끝납니다.
파일당 20MB 제한을 둡니다. 원내 서식 규모(수십~수백 MB)에서는 SQLite가 충분히 감당합니다.

## D-03. 백업
- 매일 1회 자동 백업. PC가 밤에 꺼져 있을 수 있으므로 "정해진 시각(기본 12:30) 이후 아직 오늘 백업이 없으면" 실행하고, 서버를 켤 때도 확인합니다.
- `VACUUM INTO`로 사용 중에도 깨지지 않는 사본을 만듭니다. 기본 보관 개수 30개(약 한 달).
- 복원 전에는 현재 상태를 자동으로 한 번 더 백업합니다(되돌릴 수 있게).
- 다른 PC/USB에도 복사해 두라는 안내를 GUIDE.md(백업과 복원)에 넣었습니다(같은 PC 고장 대비).

## D-04. API 키 보관
- 키는 AES-256-GCM으로 암호화해 DB에 저장하고, 암호화 열쇠는 `data/secret.key` 파일(DB 밖)에 둡니다.
  DB 백업 파일만 유출돼서는 키를 알 수 없습니다. 반대로 다른 PC로 복원하면 키를 다시 입력해야 합니다(화면에 안내).
- 키는 저장 후 브라우저로 다시 보내지 않습니다(끝 4자리만 표시).

## D-05. 로그인·세션
- 비밀번호: Node 내장 scrypt(N=16384, r=8, p=1) + 사용자별 무작위 소금값. 최소 8자.
- 세션: 무작위 토큰을 HttpOnly·SameSite=Strict 쿠키로. DB에는 토큰의 해시만 저장. **8시간 동안 사용이 없으면 만료, 최대 16시간**(하루 근무 시간 기준).
- 로그인 실패 5회 → 해당 계정 15분 잠금. IP당 15분에 30회 시도 제한.
- 첫 실행 시 사용자가 0명이면 설정 화면을 띄워 관리자 계정을 직접 만들게 합니다. 코드에 기본 비밀번호는 없습니다.
- 직원 계정은 관리자가 임시 비밀번호로 만들고, 첫 로그인 때 비밀번호를 바꾸게 합니다.

## D-06. 원내 네트워크 전용
- 기본값으로 사설 IP(192.168.x.x, 10.x.x.x, 172.16~31.x.x, 127.0.0.1 등)에서 온 요청만 받습니다. 그 밖의 주소는 403.
- 원내 통신은 HTTP입니다(원내 망 안에서만 쓰는 전제). HTTPS가 필요하면 docs/GUIDE.md 의 외부 공개 주의사항을 따릅니다.

## D-07. 개인정보 필터
- AI로 보내기 전 서버에서 검사: 주민등록번호/외국인등록번호, 휴대전화·일반전화, 이메일, 카드번호(Luhn 검사), 계좌번호 형태, 여권·운전면허 번호, "차트번호/환자번호" 표기, "OOO 환자님" 같은 이름 표기.
- **주민등록번호·카드번호는 무조건 차단**(보내지 않음), 나머지는 기본 **가리고 보냄**(예: `[전화번호]`). 관리자 화면에서 "감지되면 모두 차단"으로 바꿀 수 있습니다.
- 사용자는 무엇이 왜 가려졌는지 결과 화면에서 바로 봅니다.
- 리뷰 원문, AI 도우미 질문 같은 자유 입력 텍스트는 DB에 저장하지 않습니다(사용량 기록에는 기능·토큰·비용만 남김).

## D-08. AI 모델 등급
- 기능마다 `fast`(간단·짧은 일: 분류, 짧은 문구) / `smart`(일반 문서·요약) 두 등급 중 하나를 씁니다. 관리 화면에서 기능별로 바꿀 수 있습니다.
- 가격표(1백만 토큰당 USD)와 환율은 관리 화면에서 수정할 수 있고, 기본값은 작업 시점 공식 가격입니다([COST.md](COST.md)).
- 월 예산(원)을 넘으면 기본 **차단**, 80%에서 경고. "경고만" 모드도 선택 가능.
- 응답 대기 시간 기본 60초(긴 문서 120초). 시간 초과·키 오류·한도 초과·인터넷 끊김을 쉬운 한국어로 안내.

## D-09. 원내 AI 도우미 검색 방식
- 한국어는 조사("멸균기는", "멸균기를")가 붙어 단어 검색이 잘 안 맞습니다. 그래서 문단을 **글자 2개 묶음(바이그램)** 단위로 색인해 BM25 점수로 찾습니다.
  임베딩(벡터) API를 쓰지 않아 추가 비용·외부 전송이 없고, 원내 문서 규모(수백 쪽)에서 충분히 빠릅니다.
- 키가 없는 데모 모드에서도 "가장 관련 있는 문단"을 근거와 함께 보여 주므로 쓸모가 있습니다.

## D-10. 화면 주소는 `#/...` 방식
서버 설정 없이 새로고침·즐겨찾기가 동작하도록 해시 주소를 씁니다.

## D-11. 시간대와 금액
- 날짜는 원내 PC 시간(한국 시간) 기준 `YYYY-MM-DD`, 기록 시각은 ISO 형식.
- 금액은 원 단위 정수.

## D-12. 법정 일정 기본값
- 치과에서 흔히 챙기는 정기 의무를 예시로 넣되, **주기를 확신할 수 없는 항목은 "확인 필요"로 표시**합니다.
  법령·지자체 기준이 바뀔 수 있으므로 모든 항목은 사용자가 고칠 수 있고, 화면에 "법률 자문이 아님" 안내를 둡니다.

## D-13. 연차 계산
- 기본 계산은 근로기준법 일반 규칙(1년 미만 매월 1일, 1년 이상 15일 + 3년차부터 2년마다 1일, 최대 25일, 입사일 기준)을 따르되,
  병원마다 회계연도 기준 등 운영이 달라 **관리자가 직원별 부여 일수를 직접 고칠 수 있게** 했습니다. 5인 미만 사업장 예외 등은 화면에 안내합니다.

## D-14. 테스트
- 서버·로직 테스트는 Node 내장 `node:test`(추가 설치 없음).
- 브라우저 E2E는 `playwright-core` + **Windows에 기본 설치된 Microsoft Edge**를 사용합니다(브라우저 추가 다운로드 없음). 개발용이라 매일 실행에는 필요 없습니다.

## D-15. 데모 데이터
가상의 "하늘치과의원"과 가상 직원(김하늘 원장 등)으로 예시 데이터를 넣습니다. 환자 데이터는 예시로도 넣지 않습니다.
관리 → 초기화에서 업무 데이터를 모두 지울 수 있고(사용자 계정·설정은 유지), 다시 넣을 수도 있습니다.

## D-16. 포트
기본 포트 `3800`. 흔한 개발 포트(3000, 8080)와 겹치지 않게 골랐습니다. `config.json`에서 바꿀 수 있습니다.

## D-17. 기능 모듈은 하위 에이전트로 병렬 개발, 공통 규칙 고정 후 진행
공통 부품·디자인 시스템·모듈 규칙(docs/CONVENTIONS.md)과 본보기 모듈(공지 보드)을 먼저 만든 뒤, 서로 독립적인 모듈 5묶음을 병렬로 개발했습니다.
각 모듈은 자기 폴더·화면·CSS(mod-*.css)·테스트 파일만 고치고, 공통 파일 변경 요청은 통합 단계에서 반영했습니다. 합친 뒤 전체 테스트와 E2E를 다시 돌렸습니다.

## D-18. 모듈 하나가 고장 나도 서버는 켜짐
`server/modules/index.js` 는 모듈 파일을 불러오다 오류가 나면 그 모듈만 끄고 서버 창에 크게 알립니다.
비개발자가 운영할 때 한 기능의 문제로 전체가 멈추지 않게 하기 위해서입니다.

## D-19. 실사용 "기본 서식"과 데모 데이터를 분리
- 데모 없이 첫 설정을 하거나 초기화하면 **기본 서식**만 넣습니다: 법정 일정 기본 항목(날짜는 비움 — 마지막 완료일을 병원이 입력), 오픈·마감·주간 체크리스트 템플릿, 전화 응대 스크립트·문자 템플릿, 온보딩 템플릿.
- 근무 유형·공휴일(양력 고정일)·법정 교육 목록·지출 분류는 처음부터 표 구조와 함께 들어갑니다.
- "데모 데이터 다시 넣기"는 기본 서식과 겹치지 않도록 업무 데이터를 비운 뒤(직전 상태 자동 백업) 넣습니다.

## D-20. 재고 출고 순서
유효기간이 빠른 로트 → 유효기간 없는 로트 → 로트 없는 재고 순으로 차감하고, **이미 만료된 로트는 자동 출고하지 않습니다.**
만료품이 모르게 사용되는 일을 막기 위해서이며, 만료품은 재고 → 경고 탭의 [폐기]로 따로 처리합니다.

## D-21. 연차 기준
입사일 기준(근로기준법 일반 규칙)으로 자동 계산하고, 직원별·연도별로 직접 고칠 수 있게 했습니다(D-13). 원장 계정처럼 입사일이 없으면 자동 계산하지 않고 "—"로 표시합니다.
휴가 일수는 정기 휴진 요일과 등록된 공휴일을 빼고 계산합니다. 설날·추석·대체공휴일·선거일은 해마다 달라 병원이 직접 추가합니다(화면에 안내).

## D-22. 원내 HTTP 환경에 맞춘 보안 헤더
Cross-Origin-Opener-Policy 는 HTTPS에서만 의미가 있고 원내 IP(http)로 접속하면 브라우저 경고만 남겨 넣지 않았습니다.
같은 이유로 클립보드 복사는 HTTPS 전용 기능이 막혀도 동작하는 예전 방식을 함께 씁니다. E2E 테스트는 실제 직원 PC와 같은 조건(원내 IP + http)으로 실행합니다.

## D-23. 자유 입력 칸의 개인정보
멸균 기록의 적재물·메모처럼 자유 입력 칸에 환자 정보로 보이는 내용(전화번호, "OOO 환자" 등)이 들어오면 저장을 거부하거나(멸균 기록) 입력란 안내 문구로 경고합니다.
리뷰 원문·AI 도우미 질문처럼 환자 이야기가 섞이기 쉬운 글은 아예 저장하지 않습니다.
