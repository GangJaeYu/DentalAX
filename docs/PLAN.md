# DentalAX 계획서 (PLAN)

> 이 문서는 "무엇을, 어떤 순서로, 어디까지 만들면 완성인가"를 정리한 설계도입니다.
> 결정의 이유는 [DECISIONS.md](DECISIONS.md), 진행 상황은 [../PROGRESS.md](../PROGRESS.md)에 있습니다.

## 1. 한 줄 요약

원내 Windows PC 한 대를 서버로 쓰는 **치과 운영 업무용 웹 서비스**입니다. 환자 정보는 저장하지 않고,
데스크·재고·서류·인사·시설·지출 업무를 기록하고, 반복적인 글쓰기와 정리는 AI가 초안을 만들어 줍니다.

## 2. 사용자와 권한

| 역할(시스템) | 보통 누구 | 할 수 있는 일 |
|---|---|---|
| `admin` 원장·관리자 | 원장, 대표 | 전부. 사용자·권한, AI 설정, 백업·복원, 초기화, 감사 로그 |
| `manager` 실장 | 실장, 데스크 책임자 | 모든 업무 모듈 편집, 연차 승인, 지출·발주 관리, AI 사용량 보기 |
| `staff` 직원 | 치과위생사, 간호조무사, 데스크 직원 | 공지 읽기·인수인계 작성, 체크리스트 수행, 입출고 기록, 연차 신청, 멸균 기록, AI 도구 사용, 원내 AI 도우미 |

직종(원장/실장/치과위생사/간호조무사/기타)은 권한과 별도로 기록합니다.

## 3. 기능 목록 — 필수(MVP)와 확장

모든 기능 공통: 목록 → 검색/필터 → 추가/수정(모달) → 삭제(확인) → 활동 기록. 빈 화면·로딩·오류 상태 포함.

### A. 데스크·소통
| 기능 | 구분 | AI가 돕는 일 |
|---|---|---|

## 5. 데이터 구조 (SQLite 단일 파일 `data/dentalax.db`)

환자 이름·연락처·주민번호·차트번호·진료 정보를 담는 표나 칸은 **만들지 않습니다.**

**공통(core)**
- `users` (id, name, username?, password_hash?, role, job_title, hire_date, status, must_change_password, color, failed_logins, locked_until, created_at)
  — 로그인하지 않는 직원도 근무표에 넣을 수 있도록 username/password는 비울 수 있음
- `sessions` (id=토큰 해시, user_id, csrf_token, created_at, last_seen_at, ip, user_agent)
- `settings` (key, value JSON) — 병원 정보, AI 설정, 백업 설정 등
- `audit_logs` (id, at, user_id, user_name, action, entity, entity_id, summary, ip)
- `ai_usage` (id, at, user_id, feature, provider, model, input_tokens, output_tokens, cost_usd, cost_krw, status, pii_types, duration_ms, error)
- `secrets` (name, ciphertext, iv, tag, hint) — API 키 (AES-256-GCM 암호화, 열쇠 파일은 DB 밖)
- `_migrations` (id, applied_at)

**A 데스크**: `posts`, `post_reads`, `checklist_templates`, `checklist_items`, `checklist_runs`, `checklist_checks`, `message_templates`, `call_scripts`
**B 재고**: `inv_items`, `inv_lots`, `inv_moves`, `inv_prices`, `vendors`, `purchase_orders`, `purchase_order_items`
**C 서류**: `documents`(type: 문서/회의록), `files`(BLOB 저장 — 백업이 DB 한 파일로 끝나도록)
**D 인사**: `shift_types`, `schedule_entries`, `leave_requests`, `leave_grants`, `trainings`, `training_records`, `onboarding_templates`, `onboarding_template_items`, `onboarding_runs`, `onboarding_checks`
**E 시설**: `equipment`, `equipment_logs`, `sterilization_logs`, `compliance_tasks`, `compliance_logs`
**F 지출**: `expense_categories`, `expenses`
**G 도우미**: `kb_docs`, `kb_chunks`

## 6. 구조 (폴더)

```
start.bat / stop.bat / install.bat   매일 실행·종료·최초 설치
server/
  index.js        서버 시작(포트, 자동 백업 예약)
  app.js          웹 서버 조립(보안 → 로그인 → 모듈 API)
  core/           DB, 로그인·세션, 보안, 검증, 감사 로그, 설정, 백업, 암호화
  ai/             AI 공급자(Claude/OpenAI/Gemini/데모), 개인정보 필터, 비용·예산
  modules/<모듈>/ 모듈별 DB 표(migrations), API(routes), 예시 데이터(seed), 대시보드 요약
public/
  index.html, css/app.css(디자인 시스템), fonts/(Pretendard), vendor/(Preact+htm)
  js/ main.js, api.js, router.js, ui/(공통 컴포넌트), pages/(화면별)
tests/            자동 테스트 (node:test) + e2e/(브라우저 테스트)
data/             DB, 백업, 암호화 열쇠 (자동 생성, 깃에 올리지 않음)
docs/             문서
```
