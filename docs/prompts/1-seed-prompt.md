# ① 원 프롬프트 (아이디어)

> 원장님이 평소 말투로 직접 쓴 처음 아이디어입니다. 이 글을 그대로 AI에게 주고 "더 정확하고 세련되게 다듬어 달라"고 요청해서
> [② 확장 프롬프트](2-expanded-prompt.md)를 만들었고, 실제 개발에는 ②를 새 세션에 한 번 입력했습니다.

```text
아래의 프롬프트는 내가 일단 만든건데 좀더 정확하고 세련되게 만들어줄래? 목적은 이프로젝트 서비스를 내가 쓰려는게 아니고 원장님들이 단일 프롬프트로 아무런 스킬사용없이 순수 claude code opus 5.5 high  체급으로만 만들어보려한다 지금 컴퓨터에 별도로 설치한 플러그인(외부 플러그인)들이있는데 이거 사용전혀없이 오염없이 순수하게 단일 프롬프트로 진행하려한다. 일단 프롬프트 참고해서 다시 수정 보완해줘.

치과 병의원에서 진료 외적인 업무를 AX 하려는 시도가 많이 생기고 있다. 자체적으로 서버 구축(온프레미스)도 가능하지만, 의료민감 정보나 환자 개인정보를 다루지 않는 경우 LLM API 이용도 훌륭한 가성비로 누구나 쉽게 원내 AX를 시작할 수 있을 것 같다.

일반적인 치과 병의원에서 적용할 수 있는 원내 업무 AX 프로그램을 웹베이스로 만들고 싶다. 유저는 원장 포함 직원들이다. 가능하면 환자의 개인정보(의료정보 포함)는 건드리지 않고, 일반적인 데스크 업무부터 치과 운영을 위한 행정, 서류, 사무, 재고 등의 업무를 최대한 AX 할 수 있도록 서비스를 만들고 싶다. 외부 플러그인(스킬)은 사용하지말아줘. 자체 보안도 신경써야 한다.

디자인은 원내에서 편안하게 사용할 수 있도록 직관적이면서, 최신 웹 서비스에 걸맞게 세련된 느낌을 반드시 가지면 좋겠다. 지금 적힌 시드 아이디어를 더 확장하여 웹 서비스를 만들어줘. 필요한 경우 병렬 작업을 허용하며, 전체 서비스를 구축하기 위한 과정을 분할 하여 단계별로 진행하고 실제 단계별로 문제 없는 지 확인 및 검증 하면서 만들어줘. 최종적으로 바로 원내에서 쓸 수 있는 실제 완성 서비스가 나와야한다.

무엇보다 나의 선택과 개입은 최소화 될 수 있게 해줘. 추후 유지 보수를 위해 README 파일을 꼼꼼하게 만들어줘. 나는 코딩을 전혀 모르는 치과의사다. 이 점을 꼭 참고해줘. 그리고 코드마다 주석을 꼼꼼하게 달아서 코드를 대략적으로 확인할 수 있게 해줘. LLM API 개념도 잘 모르니깐 이것도 친절하게 안내해줘. 어떤걸 사용하면 좋을지도 서비스를 만들고 나서 추천해줘. 비용도 분석해주면 좋을 것 같다.
```
